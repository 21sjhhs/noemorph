# 多 Agent 实际调度约束

## 执行原则

主 Agent 必须使用当前运行环境**实际提供**的子 Agent/委派工具。Skill 是操作规范，不会自动创造多 Agent API。首次调用前检查子 Agent 工具是否可用；可用时使用真实调度，不能在主 Agent 中分段扮演多名独立研究者。

## 广度

1. 从逻辑拆解图按覆盖率分配 `agents` 个互补的锚点集合和方法角色。
2. 尽可能并行启动指定数量的真实研究子 Agent；如环境限制同时执行数量，则按批次调度，**总数保持与用户要求一致**。
3. 每个子 Agent 在隔离任务中独立完成五方向生成；不展示同轮其他研究者的结果。
4. 逐一检验五个问题的可区别性和可研究性。缺陷任务回到产生它的实际 Agent 修订。
5. 子 Agent 不应操作共享主状态文件；由主 Agent 接收结果、去重和登记。

## 深度

1. 主 Agent 选择 `n` 后，对每一条入选方向分配明确独立研究任务。
2. 深度任务可以复用广度阶段的实际 Agent；不要求额外新增 `n` 名 Agent，但每条研究工作须留下实际执行者的标识。
3. 向每个深度执行者提供指定方向、逻辑桥接、初始证据线索和至少三层追踪要求。
4. 深度执行者不得从未核实的中间结论开始跳跃证明；无来源则标未证实。
5. 主 Agent 专注多路径之间的连接、研究策略调整与报告综合。

## 失败条件

- 真实子 Agent 不可用：暂停并告知；只有获得用户允许才能退化为单 Agent。
- 指定 Agent 无法完成五个有效广度方向：重试当前委托，失败如实记录；不伪造。
- 证据来源访问失败：记录状态，不制造假引用；如果深度路径无法完成，解释断点并记录未完成探索。
- 运行资源不足：优先保留当前已完成的结构化研究，报告实际完成范围，不宣称完成整个大轮。

## 上下文与去锚定

- 广度委托包含结构性关系，不包含由主 Agent 主观补出的参考答案。
- 子 Agent 任务之间可以共享用户原题与正式拆解，不分享同轮即时中间结果，以减少相互锚定。
- 第二大轮起可以传递上一轮真实发现的证据摘要，但仍必须启动一次新的概念重构与五向广度探索。
- 不将同一 Agent 同一提示的重复输出称为独立知识验证。
