# 最终报告：知识保全与完整性协议

## 1. 核心原则

深度研究路径的筛选，不等于对知识价值的最终筛选。

所有广度探索中已经获得、且具有合理相关性与证据的研究发现，都必须进入最终知识整理流程。

禁止仅依据 `selected_ids` 生成最终报告。

`selected` 仅表示获得进一步研究资源，不代表其他方向无价值。

## 2. 完整知识提取

在生成最终报告之前，主 Agent 必须遍历：

- 所有大轮
- 所有广度探索 Agent
- 每个 Agent 提交的全部方向
- 全部深度探索路径

从每条方向提取：

- 原始研究问题
- 核心发现
- 新增知识概念
- 证据来源
- 不确定性
- 是否经过深度探索
- 后续研究价值

未入选深度探索的方向，必须保留其已经取得的有效发现。

## 3. 知识整合

以知识内容组织最终报告，而不是机械地按照 Agent 或轮次罗列。

允许合并语义重复的发现，但必须保留原始来源 ID。

必须区分：

- 已获得证据支持的研究发现
- 尚未深入验证的候选联系
- 已识别但仍未解决的问题
- 证据不足或被否定的联系

禁止将不同概念简单合并为一个泛化结论，导致重要细节丢失。

## 4. 三层交付结构

### 第一层：综合研究报告

系统回答原始问题，并整合全部研究中具有实质价值的发现。

报告不应只围绕深度探索入选方向展开。

### 第二层：完整知识地图

包括广度探索和深度探索中发现的全部有效概念、理论、对象和机制。

知识图谱应保留：

- 节点
- 关系
- 来源
- 探索深度
- 证据等级
- 待研究状态

### 第三层：完整研究目录

按主题展示所有原始探索方向。

每条方向至少应有一句实质性研究发现，以及对应证据或不确定性。

## 5. 完整性验证

生成报告前，执行自动检查：

1. 审计中的全部广度方向 ID 是否已进入报告整理清单？
2. 所有具有有效发现的未入选方向，是否被纳入知识地图或明确标记保留？
3. 全部深度探索结果是否进入综合报告？
4. 是否存在因摘要压缩而被错误删除的重要知识？
5. 是否建立了完整的原始 ID 到最终报告位置的映射？

若有发现未被呈现，必须明确说明排除原因。

禁止在存在未处理有效发现的情况下，将报告标记为完整。

## 6. 输出长度管理

不得因为研究结果过多，就静默丢弃研究发现。

如果完整内容超出主报告的合理篇幅，应生成独立的完整知识目录或研究附录。

主报告保留高价值的知识总结，完整资料作为单独工件交付。

## 7. 最高优先级

**探索深度决定我们研究一个方向有多详细，但不能决定这个方向已经发现的知识是否有资格进入最终报告。**

最终知识覆盖范围应以全部研究成果为基础，而不是以被选中的深度探索方向为基础。
